# 从玩家体验到系统规则：FGO 系统策划研究笔记

作者：俞帆 / Fan Yu  
整理日期：2026-10-29  
性质：个人学习、游戏观察与设计分析。配套网页提供教学交互，不是官方客户端或完整战斗模拟器。

## 阅读地图

1. 从者档案：认识职阶、卡组与角色内容。
2. 成长分析：拆分能力循环与情感循环。
3. 经济模型：用来源、库存、转换、消耗与门槛解释节奏。
4. 好友支援：从一次战斗需求，追踪到持续关系与供给维护。
5. 策划方法：把观察转化为规则、界面和可检验的问题。

本稿依据26张不同手写笔记照片整理；附件中的一张重复图片不重复计入。照片记录的是学习过程，不是开发团队的内部设计文档。新增解释与教学模拟是此次扩展内容。

## 1. 先区分证据的层级

| 层级 | 含义 | 写法示例 |
|---|---|---|
| 观察 | 实际看见或操作过的内容 | 支援列表允许按职阶查找 |
| 规则 | 条件与结果之间的确定关系 | 申请后需要对方接受才能成为好友 |
| 设计推断 | 对机制目的或行为影响的解释 | 战后申请可能让建立关系有一次使用经验作为依据 |
| 待验证 | 尚无足够证据支持的判断 | 战后入口是否提高了长期重复使用支援的比例 |

页面中的“设计解读”表示推断。原型中的虚构玩家、等级、技能值、奖励与容量仅用于演示状态变化。不能将其作为某服务器当前规则的数值依据。

### 一个更完整的分析句式

机制 → 改变的条件或成本 → 可能产生的行为 → 收益与代价 → 所需证据。

例如：按职阶筛选支援，减少与当前敌方不匹配的候选，可能缩短查找时间；但当玩家实际在找特定技能与礼装时，单一职阶维度仍可能不够。应观察完成选择的时间、刷新次数和未找到目标时的退出行为。

## 2. 从者系统：角色身份、能力与内容

### 2.1 系统边界

从者系统负责承载角色的定义、成长、内容与管理，并通过接口连接召唤、关卡、编队、战斗、经济和好友支援。分析时不必将所有外部规则重新写入从者系统；应该说明每个相邻系统提供和接收什么。

| 模块 | 玩家问题 | 输入与输出 |
|---|---|---|
| 角色定义 | 这是谁，能做什么？ | 身份、职阶、稀有度、基础能力、卡组、技能、宝具、特性 |
| 获取 | 如何加入我的收藏？ | 获取渠道与条件 → 持有的从者 |
| 培养 | 哪些东西可以改变？ | 资源与条件 → 等级、技能、阶段等变化 |
| 战斗使用 | 放进队伍后有什么作用？ | 从者、礼装、编队位置 → 可执行的战斗能力 |
| 内容与关系 | 我能进一步了解什么？ | 进度条件 → 语音、资料、卡面、幕间等内容 |
| 持有管理 | 如何查找、保护和整理？ | 筛选、排序、锁定、保管与重复个体处理 |
| 外部展示 | 我的投入如何被其他玩家看见？ | 养成结果与支援配置 → 可被浏览和借用的从者 |

### 2.2 职阶是一层匹配，不是完整定位

七基本职阶中的两个主要攻击相性环：

- Saber → Lancer → Archer → Saber。
- Rider → Caster → Assassin → Rider。

箭头表示攻击有利。网页中的基础图示对这些相性采用×2，逆向攻击为×0.5。Berserker对七基本职阶的攻击相性为×1.5，受到其他六基本职阶的攻击通常为×2，受到Berserker攻击为×1.5。Shielder在图示范围内为中性。特殊职阶、被动与具体技能不在本入门图范围内。

职阶相性倍率不是最终伤害。角色攻击力、卡种、宝具、特攻、技能、礼装等还会影响实际结果。因此，看到一个Saber，不能直接断定它适合所有Lancer关卡；还需要看关卡结构、敌方机制与队伍需求。

### 2.3 卡组与宝具如何成为分析入口

先记录固定信息：普通指令卡的Buster/Arts/Quick组成，以及宝具的卡种与效果。Buster偏伤害，Arts偏NP获取，Quick偏暴击星获取；这些只是基础倾向，实际收益还受卡位、命中数、角色参数及技能影响。

网页选取8个样本，用于训练“先看定义，再问应用”的过程，而非强度排名：

| 样本 | 适合观察的问题 |
|---|---|
| 阿尔托莉雅·潘德拉贡 | 再临卡面怎样让培养进度变得可见？ |
| 卫宫 | 职阶之外，卡组与宝具怎样影响队伍理解？ |
| 库·丘林 | 同一职阶中的个体技能如何形成不同用法？ |
| 美杜莎 | 稀有度、获取与阵容用途怎样分开分析？ |
| 美狄亚 | 卡组倾向与宝具获取之间还需要哪些数据？ |
| 佐佐木小次郎 | 从卡种推断暴击星表现时，为什么还要看命中数？ |
| 赫拉克勒斯 | 广泛攻击相性与承伤风险怎样形成配队需求？ |
| 玛修 | 剧情角色如何同时连接战斗保护和持续认识？ |

每位从者的卡面和基础记录来自Atlas Academy NA数据。宝具仅展示基础记录，不把后续强化或剧情版本合并为一个对象。最终再临卡面不在此次展示范围。

### 2.4 能力循环

获得 → 投入资源 → 完善能力或阵容 → 关卡应用 → 获得后续资源 → 再次培养。

这条循环需要分别衡量：能否通关、效率、稳定性、操作负担和阵容适用范围。不能仅用一个伤害数字判断成长是否有价值。

每项培养建议记录：

| 培养项 | 前置 | 消耗 | 结果 | 如何感知 |
|---|---|---|---|---|
| 等级 | 当前等级与上限 | 对应经验投入和费用 | 数值成长 | 等级、属性变化 |
| 再临 | 阶段与进度条件 | 阶段材料与费用 | 阶段、上限或相关内容变化 | 卡面、外观、可培养范围 |
| 技能 | 技能开放与当前等级 | 材料与费用 | 对应技能参数变化 | 说明、冷却或战斗表现 |
| 宝具 | 持有与强化条件 | 对应强化投入 | 宝具等级及对应收益 | 宝具等级、效果变化 |
| 长期扩展培养 | 对应成长前提 | 稀缺资源与其他条件 | 延伸成长目标 | 数值、阶段与展示 |

上表是记录模板，具体费用与上限按目标服务器版本补全。原笔记“100—120级”的消耗清单属于局部记录，不应视为完整配置。

### 2.5 情感循环

产生兴趣 → 使用与接触 → 了解角色 → 形成偏好或认同 → 再次投入。

这个循环是对动机的解释，不是所有玩家必然遵循的顺序。语音、羁绊、资料、幕间与外观分别有开放条件；观看内容与增强战斗能力也不是同一个结果。

值得保留的张力：

- 喜爱的角色与当前最有效率的选择可能不一致。
- 频繁使用可以增加熟悉，也可能带来重复疲劳。
- 稀缺投入可以体现偏好，也可能使试错成本过高。
- 展示让投入被看见，但被看见不自动等于被认可。

后续研究可以询问：玩家为什么继续使用某位从者？在有更高效选择时是否仍会选择它？哪些内容改变了其理解？这些问题应与实际操作观察结合。

## 3. 经济模型：从资源流解释节奏

### 3.1 不同概念属于不同层级

| 概念 | 层级 | 含义 |
|---|---|---|
| Resource | 对象 | 玩家可持有、积累和使用的东西 |
| Source | 来源机制 | 将某种资源引入分析范围 |
| Sink | 消耗机制 | 将某种资源从可用库存或流通中移除 |
| Converter | 转换机制 | 输入资源，产出另一种资源、能力或结果 |
| Intermediate resource | 资源用途 | 处于活动与最终目标之间的中间资源 |
| Gate | 限制作用 | 控制访问、频率、速度或时机 |
| Premium currency | 货币属性 | 通常与付费及受控分配有关的货币 |

一个资源可以承担多重作用。体力是资源；随时间恢复是来源；入场扣除是消耗；不足时不能入场体现门槛。不要把这些标签画成互斥的物品类别。

### 3.2 先定义分析边界

花金币在系统商店购买材料：对金币库存是流出，对材料库存是流入，对整体行为是转换。若金币退出流通，它也是金币消耗口。若金币只是转给另一个玩家，则是经济内部转移，不等于全局消耗。

因此每张资源图要标注资源名称、单位、时间范围和系统范围。

### 3.3 来源、库存与消耗

来源分为可重复、一次性、限时与付费渠道。除了数量，还要看频率、上限、参与条件和到账时点。

原笔记示例：每日任务50,000 + 普通玩法30,000 + 周奖励70,000/7 = 日均90,000金币。这个日均值假设对应参与条件成立；周奖励折算不代表每天实际到账。

单种资源库存：期末 = 期初 + 流入 − 流出。强化同时消耗金币与材料时，两个库存分别记录，不能只看金币总量。

可选消耗可能吸收高投入玩家的富余资源，但是否影响普通进程取决于收益、成本与玩家目标，不能仅凭“可选”二字判断。

### 3.4 中间资源提供什么空间

活动 → 材料 → 分配给某个目标 → 强化 → 能力变化。

中间资源允许玩家储存和延后决策，也让策划分别调整获取速度、转化比率、存储限制与多个目标之间的竞争。分析一种材料时可以问：如果直接发放成长结果，会失去哪种分配选择？

### 3.5 网页节奏实验的计算口径

这部分沿用原笔记的通用示例，不使用FGO真实奖励：

- 恢复间隔6分钟/点。
- 单次入场20点。
- 单次货币产出25,000。
- 单次升级费用50,000。
- 新增教学维度：每日材料支持8次升级。

假设无初始库存、无溢出、无额外恢复、全部体力投入同一关卡、单次产出固定：

每日体力 = floor(1,440 / 恢复间隔)  
完整关卡次数 = floor(每日体力 / 入场消耗)  
货币产出 = 关卡次数 × 单次产出  
货币可支持升级 = floor(货币产出 / 单次升级费用)  
实际支持升级 = min(货币可支持升级, 材料可支持升级)

默认得到240点体力、12次关卡、300,000货币、6次完整升级。剩余货币按实际支持升级扣除，剩余体力保留。

可尝试三个问题：

1. 当材料只支持3次升级时，增加金币产出为什么不改变升级数？
2. 当两类资源同时支持6次升级时，单独增加一种资源为什么可能无效？
3. 缩短体力恢复间隔，是否只是把瓶颈从体力移到了材料？

FGO日服官方帮助记载AP为5分钟恢复1点。网页中的6分钟是原笔记教学参数，已经在界面明确区分。

## 4. 好友与支援：以具体任务重新组织

### 4.1 系统定位

以从者支援连接战斗帮助、养成展示和轻量关系。降低阵容困难、提供长期使用价值、展示投入、建立低负担关系，是分析推断，不是已验证的业务效果。

### 4.2 两类玩家的循环

借用方：关卡需求 → 找支援 → 使用 → 判断价值 → 建立或维护关系 → 后续再次使用。

提供方：培养 → 配置 → 被使用 → 获得回报与展示机会 → 维护配置。

两条循环通过“支援实际被使用”相连。友情点属于回报通路，但不能未经分析就将其画成支撑主要养成开销的完整经济闭环。

### 4.3 入口按意图区分

| 入口 | 玩家目标 | 设计观察 |
|---|---|---|
| 好友管理 | 维护已有关系 | 容量、登录状态和支援信息帮助整理 |
| 关卡前支援选择 | 解决当前战斗问题 | 在需求明确时呈现候选 |
| 战后好友申请 | 延续一次有价值的使用 | 用实际体验支撑关系判断 |
| 支援编制 | 将自己的投入提供给他人 | 区分编辑与已保存的供给配置 |

### 4.4 交互原型的逐屏规格

| 屏幕 | 主要操作 | 状态变化 | 可见反馈 |
|---|---|---|---|
| 关卡入口 | 查看敌方与进入 | 进入选择流程 | 显示目标与下一步 |
| 选择支援 | 职阶筛选、刷新、详情、选择 | 选中从者 | 更新候选与编队 |
| 编队确认 | 检查前排、重新选择 | 确认一次借用 | 明确SUPPORT标识 |
| 战后结果 | 申请或再次出击 | 无关系→申请中 | 申请按钮更新，显示等待 |
| 申请管理 | 模拟对方接受、处理收到的申请 | 申请中→好友或拒绝 | 列表与计数更新 |
| 好友管理 | 搜索、排序、锁定、解除 | 关系与保护状态分别变化 | 锁定时禁止解除 |
| 支援编制 | 选择用途、从者、礼装、保存 | 草稿→对应用途的已保存配置 | 保存结果与用途对应 |

网页允许直接切换屏幕进行研究；需要从者的屏幕在未选择时提供返回选择入口。“模拟对方接受”是教学推进按钮，不代表玩家可以替别人接受好友申请。战斗通过结算示意呈现，不模拟真实战斗胜负。

### 4.5 状态如何拆分

关系：无关系 / 申请中 / 好友。  
申请结果：待处理 / 接受 / 拒绝。  
保护：锁定 / 未锁定。  
供给用途：通常 / 活动。  
供给配置：编辑草稿 / 已保存。  
本次使用：未选择 / 已选择 / 已结算。

这些维度可以同时存在。好友关系与关注关系也不应合并成必经的等级链；关注属于独立单向关系，其适用范围需要按版本记录。

### 4.6 从功能列表升级为设计分析

| 机制 | 可能的收益 | 可能的代价 | 观察方向 |
|---|---|---|---|
| 按职阶筛选 | 缩小候选范围 | 不能覆盖所有技能与礼装需求 | 查找时长、刷新与退出 |
| 战后申请 | 关系选择有体验依据 | 可能被快速跳过 | 展示、申请、接受、再次使用 |
| 好友容量 | 形成关系管理边界 | 清理成本、接纳新关系的阻力 | 满容量频率、解除与替换 |
| 通常/活动配置 | 分开维护不同用途 | 切换与生效规则的理解成本 | 错配、更新频率、保存反馈 |
| 锁定 | 降低误解除概率 | 整理关系多一步操作 | 锁定使用、误操作与解锁流程 |

界面好用与系统目标实现是两件事。按钮可操作、反馈正确是功能验收；能否持续满足需求要通过真实玩家研究。

### 4.7 版本附表应补什么

好友容量及增长条件、关注范围和上限、支援刷新规则、NPC限制、支援套数、生效用途、奖励对象和结算时点。网页不将原笔记的“3+3”直接定义为所有服务器统一规则。

官方入门与帮助支持支援不计入编队总COST的说明。原型只展示三人前排，完整编队还包含后备；这属于展示范围缩减，不是对完整游戏规则的替代。

## 5. 从逆向分析到可执行需求

### 5.1 三遍工作法

第一遍作为玩家：记录触发、行动、响应、反馈、新状态。  
第二遍作为策划：选择循环、资源流、状态、规则和依赖模型重建系统。  
第三遍作为研究者：解释收益与代价，列出证据，留下尚未解决的问题。

### 5.2 五种模型不要互相替代

| 模型 | 回答的问题 | 常见误区 |
|---|---|---|
| 系统循环 | 为什么回来？ | 画到奖励就停止，没有下一次行动 |
| 资源流 | 价值从哪来、如何转换？ | 将资源与机制放在同一类别 |
| 状态模型 | 对象如何改变？ | 将锁定、强化、装备串成必经路径 |
| 规则表 | 什么条件决定结果？ | 只写按钮名，没有条件与反馈 |
| 依赖图 | 系统交换什么？ | 只连名称，不标输入与输出 |

### 5.3 功能工作卡

- 功能名称：一个明确的玩家任务。
- 用户情境：为什么此时需要它。
- 范围：本次包含什么，关联谁。
- 入口与前置：何时可见、何时可用。
- 输入与操作：玩家对什么对象做什么。
- 规则与消耗：条件、数量、单位和时机。
- 状态变化：哪些字段改变，哪些对象建立关系。
- 可见反馈：文字、数值、动画、音效和可继续的动作。
- 常见分支：取消、无结果、容量已满、资源不足。
- 界面跳转：去哪里，返回后保留什么。
- 观测问题：收集信息是为了判断哪个假设。
- 验收情境：一组可重现的操作和预期结果。
- 版本记录：已确认规则与待补内容。

### 5.4 红点、引导、美术与埋点放在哪里

红点属于状态提示：定义触发条件、显示位置和消除条件。  
引导服务于真实任务：定义出现时机、目标动作、完成条件与可否跳过。  
美术音频服务于信息：明确资源用途、状态、数量、复用和反馈顺序。  
埋点服务于问题：先定义要观察的行为和计算口径，再决定记录哪些事件。

比如“支援筛选有助于快速找到目标”的假设，可观察支援列表出现到选中之间的时间、筛选和刷新次数、以及退出。不能只累计点击量就宣称体验改善。

## 6. 后续学习练习

1. 选择同职阶的两位从者，用相同模板比较固定定义、培养项和战斗接口。
2. 针对一次实际活动，补完资源的来源、限制、库存和消耗表。
3. 录制一次真实支援查找，标注每次操作与等待，解释哪里产生决策、哪里只是重复操作。
4. 为一个功能写“现状观察—设计推断—证据需求”，再写可执行规格。
5. 比较不同进度玩家的目标，检查同一机制是否产生不同收益与负担。
