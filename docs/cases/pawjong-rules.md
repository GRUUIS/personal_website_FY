# 《喵将对决 Pawjong》猫咪版 V4

本文件是当前实现规则，替代 V2 的“每局三枚鸣牌令、终局统一乘番”设计。

## 核心体验

一手成组立即得分，连续成组提高下一手倍率；借对手的牌获得额外积分。每局八巡，双方各有八次主动开河。人机可单独打开 index.html 游玩；好友可双向扫码或粘贴配对信息建立 WebRTC 直连，也可使用已配置的房间服务器。

## 牌与流程

- 共用标准 136 张牌，不回收。常态手牌 12 张；主动先摸 1 张到 13 张，选择 4 张公开。
- 主动方选择一个计分方案；双对产生两条独立对子记录。单个方案内实体牌不重复使用。
- 揭牌演出 850 毫秒，随后对方响应。有合法组合时最多等待 8 秒，没有组合则自动跳过。
- 抢牌每批最多一次，整局不限次数，不占主动回合。
- 抢牌必须同时使用 1～3 张当前公开牌和自己的手牌。吃、碰共 3 张，杠共 4 张。
- 抢牌保留主动方已得到的积分与牌谱。同一批不会再次反抢，旧牌河不可重复利用。
- 结算后主动方补 3 张，抢牌者补回贡献的手牌；下一名主动玩家再摸 1 张。
- 最后一批也按同样流程结算，然后比较积分。无限抢牌下最极端补牌量正好能由 136 张牌支持。
- 每巡交换先手。首局人机与联机都先猜猫爪：藏牌方选择画面左爪或右爪，猜中则猜方先手，否则藏方先手。每步 10 秒，超时随机选择。再战直接发牌并交换首巡先手。

## 麻将基础与本作约定

- 萬、筒、条各有 1～9；东、南、西、北、中、發、白为字牌。每种各 4 张，共 136 张，没有花牌或百搭牌。
- 相同牌必须花色与牌面都相同；三萬与三筒不是同一种牌。两张相同叫对子，三张相同叫刻子，四张相同叫杠。
- 顺子是同花色连续三张，例如三四五萬；不可混花色，9 后不能接 1。字牌不能组成顺子，中發白也不能连成顺子。
- 双对为两种不同对子；本作另设同花色四个连续数字的四连顺。每次主动公开四张，选择一个方案计分，其余牌也公开。
- 借对方公开牌组成顺子叫吃、组成刻子叫碰、组成四张相同叫杠。须同时使用中央牌与自己的手牌，各至少一张；抢牌不能只凑对子。
- 本作按八巡积分决定胜负，组合得分立即入账，无需等待传统胡牌。抢牌后补回配出的手牌，按原定顺序继续，不额外弃一张牌。

## 抢牌如何记录进牌河

抢牌作为原出牌批次的附属记录，一起归档。横向牌河每批并列展示原始四张与抢牌者配出的手牌，双方头像、你／对手及吃碰杠标签直接可见。被抢的原牌加猫爪标记，配牌用粉色描边，两组之间用分隔线区分。借来的原牌只显示一次，避免重复牌面影响算牌；无需点开详情才能看见新增公开牌。牌河标题同时显示批次数和已公开实体牌总数。

例如对方公开三萬、四萬、八筒、中，你拿三萬和四萬，配自己的一张五萬吃牌：原批次显示那四张，三萬与四萬加猫爪标记，旁边直接显示“你·吃”和五萬。牌河实际新增公开了这一张五萬；点开详情仍可放大查看完整三四五萬顺子。此时不新增一批四张记录；你下一次主动出四张时才新增批次。因此正常一局仍有 16 批、64 张原始公开牌，抢牌配出的手牌会增加牌河公开总张数，并直接展示在相应批次中。

历史批次只供回看，不能再次抢牌；抢出的组合不会形成新一轮反抢。提前结束时，结算页也保留尚未归档的当前公开批次。

## 主动计分方案

| 方案 | 有效牌 | 牌型分 | 满组奖励 |
| --- | --- | ---: | ---: |
| 对子 | 两张相同 | 10 | 无 |
| 双对 | 两种不同对子 | 两组分别算分 | 100 |
| 顺子 | 同花色三个连续数字 | 20 | 无 |
| 四连顺 | 同花色四个连续数字 | 38 | 100 |
| 刻子 | 三张相同 | 30 | 无 |
| 杠 | 四张相同 | 48 | 100 |
| 蓄势换手 | 任意四张，主动不登记组合 | 0 | 下次主动成组额外 +0.5 倍率 |

牌面点数：数牌按牌面数字，字牌每张 10。

```text
基础积分 =（牌型分 + 有效牌面点数之和）× 10
本手得分 = 四舍五入（基础积分 × 本手倍率）+ 本手所有奖励
总积分 = 历次本手得分之和
```

双对的基础积分是两个对子的合计。四连顺计作一条顺子类记录，推动顺子目标。抢牌只成标准顺、刻、杠，基础积分同表，抢牌本身不拿“主动四张满组”奖励。

## 连击、抢牌与蓄势

连续主动成组的第 1、2、3、4、5 次，倍率分别为 ×1、×1.25、×1.5、×1.75、×2；之后保持 ×2。

抢牌不增加也不中断主动连击。抢牌基础积分按 ×1 结算，并获得额外 80 分；主动连击为 2 / 3 / 4 / 5 及以上时，抢牌奖励升至 120 / 160 / 200 / 240 分。

散开清空主动连击，并获得一次蓄势。下次主动成组倍率额外 +0.5，结算后消耗；中途抢牌不消耗蓄势，再次散开也不叠加。散开本次 0 分，收益来自换牌与下一手，不额外创造无成本得分。

## 即时目标

每个目标每人每局领取一次；已经完成的目标与奖励不因后续牌型变化撤销。组合可以同时推动多个目标。

| 目标 | 条件 | 奖励 |
| --- | --- | ---: |
| 所选路线 | 三组顺子类 / 三组刻杠 / 三种对子 | 300 |
| 开杠大吉 | 一个杠 | 200 |
| 三顺 | 三个顺子类 | 200 |
| 双刻 | 两个刻子或杠 | 200 |
| 四顺成章 | 四个顺子类 | 400 |
| 四刻成阵 | 四个刻子或杠 | 400 |
| 同花成章 | 同一种数牌花色累计四条组合记录 | 600 |
| 三色齐 | 萬、筒、条各至少一个面子 | 200 |
| 四对成列 | 四种不同对子 | 300 |
| 七对成章 | 七种不同对子，保留此前四对奖励 | 500 |
| 借势连发 | 成功抢牌三次 | 200 |

每局随机一项双方公开争夺的目标：抢先三色齐、抢先三顺、抢先双刻。第一位完成者额外得 300，双方都能继续领取自己的普通目标奖励。

## 得分示例

玩家本局已有两组顺子，且连续两次主动成组，下一手出三四五六萬：

- 基础积分：（38 + 3 + 4 + 5 + 6）×10 = 560。
- 第三次主动连击 ×1.5，得 840。
- 四张满组 +100；首次三顺 +200；所选顺子路线达成 +300。
- 若抢先三顺是本局公共目标且尚无人完成，另得 +300。
- 本手合计 1740，全部立即入账；后续顺子不会重复领取三顺、路线或抢先奖励。

## 界面与反馈

- 主界面选择三花、橘猫、白猫、黑猫，角色只影响外观并记住选择。路线与昵称在开局前选择，好友可选择相同角色。
- 角色有待机、出牌、抢牌、被抢、胜利、失败六种姿态。猫爪按素材实际位置逐格裁切，等待显示爪背，揭晓显示空爪或持牌爪。
- 中央桌面下方常驻固定高度牌河，每批保留四张原始牌；头像、你／对手、巡数、组合描边与猫爪标记说明来源及抢牌经过。抢牌配出的手牌与行动标签直接并列展示，不重复展示借牌。点击放大，横滑回看时不自动跳回；结算包含尚未归档的当前批次，再战清空。
- 扫码弹窗宽度随屏幕保持约 70%，居中；桌面左右排布，窄屏上下排布，二维码随可用宽高缩放。
- 手牌保持单排。点击选牌、向上拖入桌面、横向拖动换位、自动理牌均可用。
- 选中四张后可切换合法计分方案；手牌区提供最多三种推荐，“补齐四张”保留已有选择。
- 等待对手时允许预选，不会自动出牌；手牌变动时移除已经不在手里的选择。
- 直接点击中央河牌或自己的配牌筛选吃碰杠，显示真实组合和预计收益。
- 分数滚动上涨；普通得分演出约 1.05 秒，800 分以上约 1.65 秒。演出不拦截输入。
- 连击、满组、目标、公共奖励与反超都有明确文字；音效分为点牌、成组、大牌、目标四档。
- 当前音效由 lib/feedback.ts 的 Web Audio 振荡器与音量包络实时生成：高分使用三角波，其余使用正弦波；音符依次间隔 75 毫秒，每个音符约 240 毫秒。首次点击或按键后解锁声音，暂未使用录制音频或背景音乐。
- 震动在设备支持时使用；声音、震动、减少动态效果分别可设置，也尊重系统减少动态效果设置。
- 当前积分、分差、路线目标和公共目标始终可见；完整牌谱、其他目标和得分历史在抽屉查看。
- 结算显示最大单手、最长连击、抢牌次数、已完成目标及下局挑战，支持原房再战与换路线。

## 人机与联机

规则由 shared/game.ts 共用，房间服务通过 server/game.ts 导出。人机在浏览器本地运行，每次只根据自己的手牌、公开牌谱和公共目标选牌，不读取玩家暗牌或未来牌墙。

人机主动思考约 1.6 秒，抢牌约 0.9 秒。玩家主动限时 25 秒、抢牌限时 8 秒；主动超时自动推荐高分组牌，累计三次主动超时判负。

WebRTC 直连由房主浏览器执行共同规则，只向朋友发送其私人视图。完整 ICE 信息压缩后通过邀请与回应两次交换，不配置外部信令、STUN、TURN。再战沿用连接；短暂断线暂停并等待最多 30 秒，数据通道关闭或房主刷新后需重新配对。公司 Wi-Fi 是否隔离设备，仍需实际内网测试。

可选 Socket.IO 模式由独立服务器执行规则，保留私人手牌、状态版本与原有服务器重连机制。人机刷新后重新开始，浏览器保留角色、最高分和反馈偏好。

## 交付与后续调参

- 根目录 index.html：自包含的人机试玩，不需要网络。
- 启动联机试玩.cmd：安装依赖、构建、启动房间服务并打开本机地址。
- dist/client：静态 H5 资源，支持双向配对直连；服务器房间模式另需配置房间服务。
- Pawjong-upload.zip：精简 index.html 为根目录入口，脚本在 scripts/，样式在 styles/，图片在 images/；所有资源随包提供并通过相对路径调用。当前无独立音频文件，合成音效随脚本加载，未来导入的音频素材会放到 audio/。
- dist/upload：上传包的分文件预览目录。根目录的单文件 index.html 继续保留用于本地试玩。
- npm run build:upload：只更新分文件上传目录和 ZIP；npm run build:standalone 同时更新本地单文件与上传包。
- npm run build：同步生成上述试玩入口与服务。

后续用实际试玩评估首次得分时间、平均对局时间、连续成组率、抢牌频率和主动再战意愿。当前分数和计时是首版参数，不将留存提升当作已经验证的结果。
